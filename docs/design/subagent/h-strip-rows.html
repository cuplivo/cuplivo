其它四处按你说的改了

  • 工具卡标题：只有一句 派遣子代理：修掉 test/auth 的三个用例，不追加时间——_localToolTitleFor（chat_message_widget.dart:585-623）本来就是「一个 l10n key、参数塞进句子」，和 chatMessageWidgetWebSearch(q) 同一写法。
  • 侧边栏：不缩进、不画时间（_ChatTile 本来就只有标题 + 小标签，side_drawer.dart:4987-5022）；「子代理」放在 composerDraftLabel 的位置。跳转放在分隔线点开的面板里（「打开子代理会话」+「查看父对话」）。
  • 配置弹窗：只剩 深度 / 模型。「完成后」删掉——它就是「落一条消息」，没有第二种选择。
  • 说明改成说明选项：深度 →「允许子代理再派子代理的层数」；模型 →「用哪个模型跑子代理」。

子代理的模型存在哪

v1 不存：继承父助手。预留「以后能选」的空间不用新表新列——Assistant 本身就是一段 JSON（assistant.dart:376），绘图模型已经这么存（imageModelProvider/imageModelId）。到时候加同级字段 + 全局默认，复用 ImageModelResolver 的两层解析，schema 仍是 5。

唯一的成本：一旦可选，子会话要记住自己用的是哪个模型，否则翻旧对话会看到「当时是另一个模型答的」。记在子会话 extras 里就够，v1 不做。

这一版定下的

  • 一条一行：任务名 + 状态 + 已跑多久，点进去是那个子会话。
  • 排序即优先级：等你回答的在最上面，其余按开始时间倒序。
  • 手机两条封顶、桌面三条封顶，溢出收成「还有 N 个」——照输入框工具行挤不下时收进「+」的同一套做法（chat_input_bar.dart:3927-3962）。
  • 跑完即消失；结果只在那条分隔线里。

必须接受的代价

  • 高度会变。两条就是 72px，消息区被顶上去一截，输入框位置跳动一次。手机小屏上这是可感的。
  • 和别的条抢位置。压缩中、起草中的条也在同一个位置；两者同时出现就是两三行提示顶着输入框。
  • 每条一小块信息，读起来更像列表。用户扫一眼的其实是「有没有事需要我做」，而不是三个任务名。
  • 「还有 N 个」是个死胡同：收起来的那几个，还是得点开面板才看得到。

两个变体共用：工具卡只写 派遣子代理：…、侧边栏单行标签、配置弹窗只剩深度与模型、模型 v1 不持久化、分隔线承载结论、ask_user 不禁用。这个变体唯一要你定的：每个子代理一行（H），还是一条汇总（G）。
