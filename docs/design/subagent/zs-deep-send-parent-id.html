深层委派：父对话 ID 写进描述

深度 2 子代理的 send_message：job_id 可选；省略、或传入父对话的 ID，都是回委派方；传孩子的 job_id 是向下。父对话 ID 直接写在工具描述里，模型不用猜。

子代理看到的 schema 与描述

{
  "name": "send_message",
  "description": "Send a message to another conversation in this
    delegation. Omit `job_id`, or pass the delegator's conversation id
    `c-123`, to reply to your delegator. Pass the `job_id`
    of one of your own subagents to message it.",
  "required": ["text"],
  "properties": {
    "job_id": { // optional: a child's id, or the delegator's id },
    "text":   { // what to say }
  }
}

三种调用

调用落到哪
send_message({"text": "缺 config"})父对话（默认）
send_message({"job_id": "c-123", "text": "缺 config"})父对话（显式 ID，同一个结果）
send_message({"job_id": "c-42", "text": "改用 YAML"})自己的孩子 c-42

根对话的 schema 不变

{
  "name": "send_message",
  "description": "Send a message to a subagent you started; it arrives
    in that conversation and does not end your turn.",
  "required": ["job_id", "text"]
}

处理器的路由

// 子代理的 send_message
target = args["job_id"]  // 可空
if target.isEmpty or target == parentConversationId:
    sendToParent(text)
else:
    sendToChild(jobId: target, text)   // 父子校验照旧

孩子的 job_id 来自 delegate 的返回值，不额外列名单；描述只多一句父对话 ID。
