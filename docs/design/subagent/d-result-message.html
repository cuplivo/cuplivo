侧边栏（v1，与 C 相同）：子会话平铺在同一个日期分组里，标题前一个 子代理 小标签。零结构改动——ChatItem 只有 id/title/created/isPinned。嵌套要另做。

配置页（与 C 相同，多一行）：「本地工具」里的一行，子行抄 _ImageToolRow 的自适应展开（chat_tools_sheet.dart:598-640）。D 多出一个「完成后做什么」，因为它多了一笔没人按按钮的计费，得让用户能关掉。

工具卡复用（与 C 相同）：通用工具卡 _ToolCallItem（chat_message_widget.dart:7180）+ ImageJobCard 的 elapsed/onOpen/ListenableBuilder 写法（:3230）。差别：D 的卡里只放任务与状态，结论在消息里——同一件事两处存放，改一处要同步另一处。

这一版定下的

  • 结果落成一条新的 assistant 消息：用户在时间线上直接看到，不需要打开卡。
  • 到达时机由「父回合是否还在跑」决定：在跑就排队到本轮结束，跑完了就直接落。
  • 可选唤醒：落消息后再跑一轮父模型，让它就这个结果说一句——这是 D 里最像 DSH 的部分。

必须接受的代价

  • 截图里是「父回合已经结束、正在等唤醒」，可你花了钱轮的这段时间父代理还有事情在做。「它什么时候能成功」取决于它被派出去以后父代理走了多远、在做什么，以及造成的延迟可能超过子代理本身。
  • 父代理正在跑时到达，本轮看不到结果：排队则结果晚一轮；打断则把话截断。
  • 唤醒是一次静默计费。不唤醒，消息可能被划过去；唤醒，用户不在场也花钱。
  • 非用户触发的会话写入：要过 LAN sync、备份、上下文压缩，要防重复投递，还要回答「谁在说话」。

分水岭

D 是结果自己走进对话：它属于父会话，属于那段历史。好处是用户什么都不用做；代价是这个应用从此有一个没人按发送键也说话的入口。

两个变体共用：工具立即返回、父会话继续干活、继承父会话的助手与工作区、深度默认 1、子会话禁用 ask_user 与审批类工具、幂等键 = 父会话 + 消息 + toolCallId、中断由渲染层派生、侧边栏与配置页相同。这个变体唯一要你定的：结果落在卡里（C），还是落成一条消息（D）。
