侧边栏与配置（与你说的对齐）

侧边栏是单行。_ChatTile 只有标题 + 小标签 + 时间（side_drawer.dart:4987-5022），没有头像、没有预览行。子代理 三个字放在 composerDraftLabel 那个位置（11px、cs.primary）。

配置收成一个入口。工具箱里一行带概要，点进去是这个弹窗；深度 / 模型 / 完成后都在弹窗里，不铺子行。

图标 Lucide.Bot（lucide_adapter.dart:33）。

消息身份：群聊那套「作者」机制，不用新造

你问的 user 消息 + extra body，仓库里已经跑着一份：群聊把别人的发言存成 role: 'user' + senderId，序列化时打 _groupPeerSender（message_builder_service.dart:653-665），由 isUserInputMessage 统一排除在「用户自己的话」之外（request_image_context.dart:35-49）——附件、图片、修订 id、「最后一条用户消息」全走这一个谓词。

  • 存：role: 'user'、senderId: 父助手.id、id = subagent-result:<childId>（幂等，重复投递天然去重）。
  • 发：wire 上是 user + 内部标记，provider 出站前剥掉（chat_completions_api.dart:368）。
  • 不接管修订 id / 附件 / 「最后一条用户消息」——那个 else if 链里加一个分支。
  • 因为 senderId 指向本助手，界面就自然解析出同一个头像和名字；标签由 id 前缀判定。

这一版定下的

  • 结论就在时间线上，不用点开任何东西——这是选 D 的全部意义。
  • 它不是「父助手说的话」：标签 + 独立消息说明它来自子会话，父模型收到的是 user 轮次。
  • 时间线里 delegate 仍是普通工具卡；运行态在输入框上方；侧边栏单行 + 标签；配置一个入口。
  • 父还在跑时，排队到当前 tool call 结束、在 step 边界插入。
  • ask_user 不禁用：子会话能交互，它在那里等回答。

必须接受的代价

  • 两段话的观感。父助手刚说「我先不动手」，紧接着又冒出一段结论；用户要自己把它读成「同一件事的两段」。
  • 父会话被打断一次。结果插在当前回合中间时，父助手的叙述会被切开——它得在下一轮里接上。
  • 界面说「助手说了」，wire 上说「用户发的」。这套不对称群聊里已有，但在这里是新的，注释得写清楚。
  • 可编辑/可重试的语义要拦。这条消息不是用户写的，编辑和重试都要藏起来，否则改一条子代理的结论会让父模型困惑。

ask_user 与审批：异步之后不用禁了

上一版写「禁用 ask_user」，前提是 wait-only（父会话被挡着）。异步之后这个前提没了：ask_user 在子会话里就是一张普通提问卡，子轮次停在那里等，父会话早就往下走了；审批卡同理（_matchingApprovalRequest 按 conversationId + toolCallId 匹配）。父侧只需一个「它在等你回答」的状态，不做透传——透传要在父会话再造一张卡，还得回答「父回合已经结束了，这张卡算谁的」。

代价：没人打开子会话，它就停着，不花钱也不产出，父侧的条会一直显示它在等。

两个变体共用：普通工具卡 + 输入框上方条 + 侧边栏单行标签 + 配置弹窗、wire 上是 user + 标记、排队到 step 边界插入、ask_user 不禁用。这个变体唯一要你定的：结论画成一条回复（F），还是一条分隔线（E）。
