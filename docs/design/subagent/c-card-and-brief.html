这一版定下的

  • 父会话在子代理运行期间继续工作：调工具、读文件、往下写，不等它。
  • 结果写进调用它的那张卡（_ToolCallItem + live registry），不新增消息类型，不新增持久化结构。
  • 父模型通过下一轮请求里的一段简报得知结果；父空闲时不打扰用户，等下一次开口。
  • 侧边栏平铺 + 标签；配置就是「本地工具」里的一行加一个深度子行。

必须接受的代价

  • 用户可能根本不看卡。父会话闲下来以后，答案就静静躺在那一格里；不新消息、不弹窗、不提醒。
  • 父模型只记得一次。简报注入一次就清，之后再问「刚才那个修好了吗」它答不上来，只能靠用户自己翻卡。
  • 「还在跑」也要占上下文。每轮一行状态注入，长任务会一直带着；要不要压缩成一行计数，实现时再定。
  • 卡里放长文有上限。子代理结论几百字可以，几千字就得截断 + 「打开」，截断规则要定。

分水岭

C 是结果留在原地：它属于那次调用，不属于对话。好处是不造新东西、不悄悄计费；代价是「结果」得用户自己走过去看，而模型只能记住一次。

两个变体共用：工具立即返回、父会话继续干活、继承父会话的助手与工作区、深度默认 1、子会话禁用 ask_user 与审批类工具、幂等键 = 父会话 + 消息 + toolCallId、中断由渲染层派生。这个变体唯一要你定的：结果落在卡里（C），还是落成一条消息（D）。
