把「本助手」摆进选择面，「无」这个词不再出现

「可委派的目标」说的其实只有一半：派给本助手的分身永远可以，这一行管的是除它之外还能指名谁。现在弹层里只列别人，空态写「无」，读起来就成了「一个都派不出去」。A 的做法是把那一半摆出来：弹层顶部是本助手（勾着，不能取消，因为它不是一个选项，是默认形态），下面是可勾选的其它助手。这一版按意见精简了描述、并把值统一成本助手 + N 个。

这一版改三处字与一处结构

  • 弹层顶部加一个分区头 + 一行「本助手 · 分身」（勾选态、不可点），下面分区头「还可以指名」。其余行原样。
  • 行标签仍是可委派的目标；值从「无」变成「本助手」/「本助手 + N 个」——统一用数量，不再显示单个助手的名字（+1 时名字已经把值挤满）。
  • 行描述精简为「可作为子代理的助手」：弹层里已经写了分身总是可派，这一行只说它管什么。
  • 工具箱那行摘要补一段：继承本助手 · 目标 2 个 · 深度 1（只列摘要，点进去还是这个弹窗）。

行：值里先说本助手

「本助手」＝没勾任何人时的值。「本助手 + 2 个」＝勾了两个；勾一个也写「本助手 + 1 个」，不写那个助手的名字——行右侧只剩一个名字的宽度，多一个字就截断，数量反而稳定。

描述只说它管什么：分身总是可派这件事由弹层的分区头说，行上不重复。

为什么保留「可委派的目标」这个名字：它是这一组设置的名字；改描述就够说清它管的是「除分身之外」。

工具箱摘要：继承本助手 · 目标 2 个 · 深度 1。没勾任何目标时仍只写 继承本助手 · 深度 1，一个字不多。

弹层：两段，一段固定一段可选

「本助手」不是开关：勾是勾着的，点不动。它不是一个可选项，是这个功能默认的样子；做成能取消的开关，就要回答「关掉以后模型还能不能派给自己」，那是一个新问题。

下面那段才是这一行管的，分区头写「还可以指名」。底部一句「不勾任何人，就是只派给本助手」——空态的解释放在它该在的地方，而不是塞进一个「无」。

实现：给复用的 GroupMemberPicker 加两个可选参数（header / footer），群聊调用不传，行为不变。行仍是头像 + 名字，本助手那行用当前助手的头像。

模型侧：一个字不改

  • 没勾任何其它助手 → target 参数仍然不出现，schema 与发布前逐字节相同；模型照样派给本助手。
  • 勾了 → 枚举仍是 general + assistant:<id>，描述里第一行就是 general — a copy of yourself.。
  • 所以这一轮只动界面与三处文案，不动契约、不动数据、不动测试口径（序列化那两条断言不变）。

代价

  • 共享的 picker 多两个可选参数：群聊那条路不传，但要保证不传时布局与今天一模一样（一次群聊邀请的回归测试）。
  • 弹层多两段，比一列到底长一点；换来的是「默认形态」和「可选项」不再混在一列里。
  • 「本助手」那行点不动：有人会想点。右上角写「总是」，用文字先回答它。

这一轮只确认：按这两条改后的 A——弹层分两段、本助手固定一行、值统一写「本助手 + N 个」、描述精简为「可作为子代理的助手」。确认后直接改，再走一次同样的界面验证。
