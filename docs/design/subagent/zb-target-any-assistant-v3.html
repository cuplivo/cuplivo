描述：一个设置，不是身份

为什么不在名称下面：身份卡回答「它是谁」；描述回答「其它模型眼中的它能做什么」，只有群聊和委派两处读。放进名称旁边，是给一个多数人不填的字段占最好的位置。

为什么在「默认工作区」之后：上面五个是模型参数，「默认工作区」是它在哪工作，描述是它对外是什么——三个「关于这个助手」的导航行连在一起，下面四个开关仍是一整组。导航行不被开关切开。

形状照抄 Max tokens：行右侧是值（空着就空着，不写「未填」），点开是同一个弹层——X / 标题 / 保存、自动聚焦的输入框、下面一行 12px 说明。说明与问号同一句话。

问号是现成的 TipIcon（_iosNavRow(tip:)）：桌面悬停、手机点一下或长按。桌面端不走弹层：labelWithHelp + 行内输入框，和桌面版 Max tokens 一致。

占位：「例如：把需求写成 SQL 并解释执行计划」——教的是写能做什么。

可委派的目标：一行 + 多选

行放在「深度」和「模型」之间——多深、派给谁、用什么模型、能花多少权限，四个问题按这个顺序。值只有三种：全部助手（默认，null）／无／N 个。没有其它助手时整行不出现。

多选沿用 showAssistantMoveSelector 的行（头像 + 名字，按用户拖好的顺序），勾选框换成 IosCheckbox；名字下面的小字就是描述——这一屏顺便让用户看到「描述」是给谁看的。手机弹层、桌面对话框，和「提权访问」同一个开关。

全选 / 全不选在弹层标题栏。全选保存写回 null（「全部助手」= 以后新建的也算），全不选写 []——「无」就是今天的行为，target 参数整个不出现。

删掉的助手从别人的名单里顺手摘掉，不让死 id 进备份和同步。

工具契约：名单来自筛选，其余不变

{ "name": "delegate",
  "parameters": {
    "task": "…", "label": "…",
    "target": {
      "type": "string",
      "enum": ["general", "assistant:<id₁>", "assistant:<id₂>"],   // 筛选后的名单，永远不含自己
      "description":
        "Who runs the task, in this same workspace:\n" +
        "general — a copy of yourself.\n" +
        "assistant:<id₁> — SQL 专家：把需求写成 SQL 并解释执行计划\n" +
        "assistant:<id₂> — 翻译官" } },                       // 描述空着就只有名字
  "required": ["task", "label", "target"] }
// 名单为空（只有一个助手，或筛成「无」）→ target 参数整个不出现，schema 与今天逐字节相同。
// 名单外 → { "status": "rejected", "reason": "unknown_target" }。回执原样带回 target。

谁贡献什么（与 v2 相同，不再展开）

  • 目标出系统提示 / 模型 / 工具集 / MCP / 技能 / 记忆；调用方出工作区（defaultWorkspaceId 永不参与）/ 提权 + 上限 / 深度；父会话的续写仍是调用方。
  • 模型解析的接缝：resolveSubagentModel(delegator, target)，签名带 target；今天两种目标同一答案（调用方覆盖 → 目标自己的 → 全局），测试按 kind 各钉一格。
  • 一个词表一处解析：subagent.target = 'general' | 'assistant:<id>'，工具参数原样落库，单一 parse / encode。schema 仍是 5。

数据

  • Assistant.description：String，默认空。读者只有两处：委派名单；群聊导演的 roster（group_director.dart:205-212）与决策 state（:359-362）——非空才加键，老用户请求字节不变。
  • Assistant.subagentTargetIds：List<String>?。null = 全部；[] = 无；否则指定的。名单按它解析，不存在的 id 跳过。
  • SubagentEntry.assistant 不动（调用方），多 targetName 给面板。幂等键、结果消息、分隔线、队列不变。

失败模式

什么坏了系统做什么
写了名单外的 targetrejected: unknown_target——删在请求与调用之间，或筛选在中间收窄，或模型写错 id。模型改派 general 或告诉用户，不留空子会话。
目标在子代理跑的时候被删子会话按既有规则解析助手，不中断；卡片名字查不到就回落到 派遣子代理：<label>。
目标的模型 / provider 没了既有的 turn_not_started：子会话留空、条不出现、模型拿到拒绝。
目标一个工具都没开子代理就是没工具，和直接跟它聊一样。
描述空着名单里只有名字。

代价

  • 不筛就全付。一个 UUID 约 15 个 token，名单里出现两次：5 个助手约 250 token，40 个约 2000。筛成 3 个就只付 3 个——这是筛选存在的理由。
  • 模型要照抄 id。抄错 → unknown_target → 重派。导演按 id 选人已经跑通，同一种用法。
  • 两个新字段走 Assistant 的 copyWith / JSON / update 管线；基本页多一个导航行，子代理弹窗多一行和一个多选。
  • 助手一多，模型可能选错人。代价是一次失败的委派，不是数据损坏。
