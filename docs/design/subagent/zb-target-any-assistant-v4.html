多选：群聊「邀请」那个窗口，原样

showGroupMemberPickerDialog(context, title:, candidates:, initialSelection:)——GroupMemberPicker：头像 32 + 名字 + CheckCircle/Circle，底部一行标题和「保存」。手机 showCustomBottomSheet，桌面 AlertDialog 360×380。调用方式和群聊 _invite 一字不差，只差排除自己、带上 initialSelection。

不显示描述：这个窗口是给用户选自己建的助手，名字够用。描述是给模型的，只在名单里出现。

行上的值：没选 → 「无」；一个 → 那个助手的名字；多个 → 「N 个」。没有其它助手时整行不出现。

保存空选 = 无（群聊邀请那条路把空选当取消，这里不是）。取消（返回 null）不写。

工具契约：不配置，参数不存在

谁贡献什么（与 v2 相同，不再展开）

  • 目标出系统提示 / 模型 / 工具集 / MCP / 技能 / 记忆；调用方出工作区（defaultWorkspaceId 永不参与）/ 提权 + 上限 / 深度；父会话的续写仍是调用方。
  • 模型解析的接缝：resolveSubagentModel(delegator, target)，签名带 target；今天两种目标同一答案（调用方覆盖 → 目标自己的 → 全局），测试按 kind 各钉一格。
  • 一个词表一处解析：subagent.target = 'general' | 'assistant:<id>'，工具参数原样落库，单一 parse / encode。schema 仍是 5。

数据

  • Assistant.description：String，默认空，单行。读者只有两处：委派名单；群聊导演的 roster（group_director.dart:205-212）与决策 state（:359-362）——非空才加键，老用户请求字节不变。
  • Assistant.subagentTargetIds：List<String>，默认空 = 无。名单按它解析，不存在的 id 跳过；删除助手时从别人的名单里顺手摘掉。
  • SubagentEntry.assistant 不动（调用方），多 targetName 给面板。幂等键、结果消息、分隔线、队列不变。

失败模式

什么坏了系统做什么
写了名单外的 targetrejected: unknown_target——删在请求与调用之间，或名单在中间收窄，或模型写错 id。模型改派 general 或告诉用户，不留空子会话。
目标在子代理跑的时候被删子会话按既有规则解析助手，不中断；卡片名字查不到就回落到 派遣子代理：<label>。
目标的模型 / provider 没了既有的 turn_not_started：子会话留空、条不出现、模型拿到拒绝。
目标一个工具都没开子代理就是没工具，和直接跟它聊一样。
描述空着名单里只有名字。

代价

  • 不配置零成本：参数不出现，令牌一个不多。配置了才付勾中的：每个约 50 个 token（UUID 在名单里两次 + 名字与描述）。
  • 模型要照抄 id。抄错 → unknown_target → 重派。导演按 id 选人已经跑通，同一种用法。
  • 两个新字段走 Assistant 的 copyWith / JSON / update 管线；基本页多一个导航行，子代理弹窗多一行（多选零新控件）。
  • 功能默认不可见——这是「默认无」的代价，也是它的意思：不勾，什么都没变。
