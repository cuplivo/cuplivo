上一轮留下的 5 个问题 · 建议答案

原文：这些必须一起定，不然开了就是坑。

  1. 面板只列直系。每一层的会话各有自己的面板，只列自己派出的子代理；带下级的子代理行加一个「+N」，点进去就是那个子会话，用已有的「回到上级」链接回来。
  2. Stop 停整棵子树。停哪一行，就以它为根整条链一起停；停最上面那行就是全部停。
  3. 错误只回上一层。任何一层失败，对它的直接上级就是一个失败的 job 结果，由上级模型决定重试、改派还是上报；本会话只看到最终结果。
  4. token：默认 1，直说成本，不加硬限制。选到 2 或 3 时，选项旁边写明"每多一层多一个独立上下文"。
  5. 提权沿链只收窄不放宽。生效的是链上最严的那个（始终拒绝 < 询问 < 始终允许）；第 2 层起的委派不再提供提权选项。

上限怎么沿链传

本层还能再派几层 = min(上一层传下来的剩余层数 − 1, 本层助手设的深度 − 1)，最小 0 发起那一层的设置决定整条链的上限；中途的助手只能把它调低，不能调高。

要跟着层号走的地方

  1. subagent_rules.dart：kMaxSubagentDepth 常量换成沿链传递的剩余层数；mayDelegate 按它判断。
  2. local_tools_service.dart：delegate / await_job 是否下发，按剩余层数决定。
  3. subagent_coordinator.dart：begin() 记录层号并传给子会话；Stop 级联到整棵子树。
  4. subagent_panel.dart / subagent_task_strip.dart：直系列表加「+N」。
  5. await_job / 提权：失败回上一层、提权取最严——两条新规则，各要状态表和测试。
