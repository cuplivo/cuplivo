深层委派：一个 send_message，job_id 可选

深度 2 的子代理既是别人的子代理，又是自己孩子的委派方。它只学一个消息工具：不给 job_id 就是回委派方，给了就是发给自己的某个孩子。

这个子代理看到的委派工具

工具用途参数
delegate再派一层（受 levels 限制）task, label（+ target）
await_job等某个孩子结束job_id
send_message向上回复 / 向下发消息text；job_id 可选
interrupt叫停自己的孩子job_id

schema

根对话（委派方）

没有委派方，只能向下
{
  "name": "send_message",
  "required": ["job_id", "text"],
  "properties": {
    "job_id": { // 哪个孩子 },
    "text":   { // 说什么 }
  }
}

深度 2 的子代理

有委派方，也可能有孩子
{
  "name": "send_message",
  "required": ["text"],
  "properties": {
    "job_id": { // 可选：给了就是发给自己的孩子 },
    "text":   { // 说什么 }
  }
}

两种调用

向上：回委派方

send_message({ "text": "读到第 3 层了，缺 config" })

不传 job_id。消息落在委派方对话里，作为一条「子代理消息」。

向下：给自己的孩子

send_message({
  "job_id": "c-42",
  "text":   "改用 YAML"
})

传 job_id。消息落在那个孩子的对话里，作为一条「委派方消息」。

一轮的样子

深度 2 子代理delegate → 拿到 job_id: c-42，继续干活
c-42send_message（无 job_id）→ 深度 2 子的对话里出现「子代理消息」
深度 2 子代理send_message({job_id: c-42, text}) → c-42 里出现「委派方消息」
深度 2 子代理interrupt({job_id: c-42}) → c-42 停下；不写结果行

代价：一个工具两个方向，模型必须读懂「省略 job_id」这层含义；描述里要写清楚，否则它可能只会用其中一个方向。
