其它四处按你说的改了

  • 工具卡标题：只有一句 派遣子代理：修掉 test/auth 的三个用例，不追加时间——_localToolTitleFor（chat_message_widget.dart:585-623）本来就是「一个 l10n key、参数塞进句子」，和 chatMessageWidgetWebSearch(q) 同一写法。
  • 侧边栏：不缩进、不画时间（_ChatTile 本来就只有标题 + 小标签，side_drawer.dart:4987-5022）；「子代理」三个字放在 composerDraftLabel 的位置。跳转不塞进侧边栏——放在分隔线点开的面板里（「打开子代理会话」旁边就是「查看父对话」）。
  • 配置弹窗：只剩 深度 / 模型两项。「完成后」删掉——它就是「落一条消息」，没有第二种选择，写出来只是多一个要读的词。
  • 两项的说明改成说明选项：深度 →「允许子代理再派子代理的层数」；模型 →「用哪个模型跑子代理」。

子代理的模型存在哪

v1 不存：继承父助手，什么都不写。要预留「以后能选子代理模型」的空间，落点不用新表新列——Assistant 本身就是一段 JSON（assistant.dart:376 的 toJson），绘图模型已经这么存了（imageModelProvider/imageModelId）。到时候加两个同级字段 + 一条全局默认，复用 ImageModelResolver 那套「助手 → 全局、配对被删就回落」的两层解析，schema 仍是 5。

唯一的成本是：一旦有了子模型，子会话的记录要记住它用的是哪个，否则重看旧对话会发现「当时是另一个模型答的」。Conversation 或子会话 extras 里记一个 model id 就够，v1 不做。

这一版定下的

  • 输入框上方恒定一行：一个显内容、多个显汇总，状态优先级「等你回答 > 在跑」。
  • 完成即消失，不在条上重复结果；结果只在那条分隔线里。
  • 手机 36 / 桌面 24 最小高，数值照 ContextTaskBar；宽度继承输入框那一列，桌面和手机都不用另立布局。
  • 点开是面板：逐个列出，进去是子会话。

必须接受的代价

  • 多个时看不见是谁。「2 个在跑」不说是哪两件，用户要点一下才知道——这是恒定高度的直接代价。
  • 「等你回答」只能给一个数字。三个都在等你回答时，条上只写 3，先答哪一个得进面板看。
  • 状态优先级是写死的：橙点抢眼只是因为它是唯一需要用户动手的状态，没有第二层信息。

两个变体共用：工具卡只写 派遣子代理：…、侧边栏单行标签、配置弹窗只剩深度与模型、模型 v1 不持久化、分隔线承载结论、ask_user 不禁用。这个变体唯一要你定的：条是一条汇总（G），还是每个子代理一行（H）。
