选中浮出翻译 chip，右键复制/复制 Markdown/翻译/全选；预览没有消息，所以只有“引用”消失，其余共用同一条逻辑。

选中后：浮出翻译 chip

没有“引用”：预览没有消息，引用动作不出现。其余与 ChatMessage 共用同一套菜单与悬浮条。

统一后的逻辑（伪代码）

// 一份选区会话：消息和预览共用
sealed class SelectionSession {
  String get sourceText;              // 选中范围的 Markdown 源
  SourceTextMap? get sourceMap;
  bool get canQuote;                  // 只有消息能引用
  ({String? provider, String? model,
    String? conversation}) get translation;
}

// 聊天消息：和现在完全一致
SelectionSession messageSession(ChatMessage m) => (
  sourceText: m.content, sourceMap: m.sourceMap,
  canQuote: true,
  translation: (
    provider: settings.translateModelProvider
              ?? conversationModel(m).providerKey,
    model:     settings.translateModelId
              ?? conversationModel(m).modelId,
    conversation: m.conversationId,
  ),
);

// 预览：同一条链，只是没有消息可引用
SelectionSession previewSession(String source) => (
  sourceText: source, sourceMap: null,
  canQuote: false,
  translation: (
    provider: settings.translateModelProvider
              ?? currentConversationModel.providerKey,
    model:     settings.translateModelId
              ?? currentConversationModel.modelId,
    conversation: currentConversation?.id,   // 没有会话 → null
  ),
);

// AppSelectionArea：菜单/悬浮条只问 session，不再问 message != null
Widget _quickBar(SelectionSession s, SelectionSnapshot snap) =>
  SelectionQuickToolbar(
    onQuote: s.canQuote ? () => _quote(s, snap) : null,
    onTranslate: () => _translate(s, snap),
  );

List<ContextMenuButtonItem> _menu(SelectionSession s) => [
  copy(s.selectedText),
  copyMarkdown(s.selectedMarkdown),
  copyRich(s),
  if (s.canQuote) quote(s),      // 预览没有
  translate(s),
  selectAll,
];

// 翻译面板不再强制 ChatMessage，只接它真正需要的三元组
showSelectionTranslationPanel(
  text: snapshot.text, anchor: anchor,
  providerKey: s.translation.provider,
  modelId: s.translation.model,
  conversationId: s.translation.conversation, // 预览可为 null
);

English: one selection session; the preview supplies no message, so quote disappears and translation resolves through the same chain, with a nullable conversation id.

为什么这样改

  • 统一的是菜单、悬浮条、翻译入口；分身的是“能不能引用”和翻译模型从哪来。
  • 翻译面板不再强制 ChatMessage，只接收 provider/model/conversation；预览的 conversation 可为 null。
  • 伪代码就是实现边界：一个 SelectionSession，聊天和预览各造一份。
代价：需要把 AppSelectionArea 从“message != null”改成“session”，并给预览补一份翻译目标解析。
