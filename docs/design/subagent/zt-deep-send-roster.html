深层委派：描述里再带孩子名单

同样的可选 job_id 与父对话 ID，额外把当前每个孩子的名字与 job_id 拼进描述。模型不必记住 delegate 的返回值，就能直接点名。

子代理看到的 schema 与描述

{
  "name": "send_message",
  "description": "Send a message to another conversation in this
    delegation. Your delegator is `c-123`: omit `job_id`
    to reply to it. Your subagents right now:
    - c-42 — 工作区内容调研
    - c-57 — 依赖审计",
  "required": ["text"],
  "properties": {
    "job_id": { // optional: a child's id, or the delegator's id },
    "text":   { // what to say }
  }
}

三种调用

调用落到哪
send_message({"text": "缺 config"})父对话（默认）
send_message({"job_id": "c-123", "text": "缺 config"})父对话（显式 ID）
send_message({"job_id": "c-42", "text": "改用 YAML"})自己的孩子 c-42（描述里已经列出）

名单从哪来

// 工具表每次请求都会重新构建
children = conversations where extras[parent] == this conversation
for child in children:
    line = "- {child.id} — {child.title}"
description += "\n\nYour subagents right now:\n" + join(lines)

代价：每轮 prompt 多出孩子名单（每个孩子一行）；名单随 delegate/结束变化，工具表要按会话状态重建——目前工具表是每请求重建的，代价可控。
