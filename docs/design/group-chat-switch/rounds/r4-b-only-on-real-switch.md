# 第 4 轮·B｜按「切换」二字收窄：只有换到**另一位**助手时才新建

> 名字说的是「切换助手时」，那就在真的切换时新建；点当前这位助手不算切换，回到它最近的会话。
> 更贴合文案，但**改掉今天一个开关开着时的行为**。

## 1. 规则

| 开关 | 点助手 A 时 | 点群 G 时 |
| --- | --- | --- |
| **开** | 当前会话的 owner ≠ A → 开 A 的新会话；<br>当前会话的 owner == A → 打开它最近的 1:1（通常就是当前这条，等于不动） | G 的最近话题，没有就新建 |
| **关** | A 的最近 1:1；没有就新建 | 同上 |

判定用的是第 2b 轮定下的 `ownerOf(当前会话)` ——「是不是同一个 owner」这件事已经有唯一答案，
所以这一格不需要新机制，只多一次相等比较。

## 2. 为什么值得考虑

- 文案与行为一致：一个叫「切换助手时新建」的开关，在你没有切换的时候不该生效。
- 开关关着时点当前助手 = 不动；开关开着时也 = 不动。两种状态在这里收敛，
  用户不必记住「同一下点击，两个开关给出两种结果」。
- 顺带消掉一个次生困惑：从群话题点助手（A 行）现在开新会话，是因为**换**了 owner，
  而不是因为开关开；规则只有一条，不依赖「当前在不在群里」。

## 3. 代价

- **改掉了今天开关开着时的行为**：在 A 的会话里再点 A，今天会得到一张新的空会话，
  改完之后不会。这是一个用户可见的回归面，不在目标书 §4 的横切豁免里
  （那一句只保证「开关关闭时」不变）。
- 「开一张新会话」在开关开着的路径上失去入口。要新建仍然可以：切到别的 owner 再切回来、
  或者是群话题里用「＋」。这比 A 变体多一步。
- 与 F 行「1:1 → 1:1 不变」的读法有关：若「不变」被理解成「与今天逐格相同」，
  那么开着开关的 A→A 这一格就破了；只能把它理解成「A→B 不变」。

## 4. 适合

认为「设置的名字必须是它能做的事的完整描述」，并且愿意为这句一致性付一次行为变更，
同时接受目标书 §4 F 行的「不变」按「换助手时不变」来解释。
