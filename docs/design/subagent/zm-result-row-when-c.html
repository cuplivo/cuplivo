结果行何时出现

它只负责把模型还不知道的结果送进对话；模型已经通过工具调用拿到结果时，它不该出现。用户取消是例外——那条线是给人看的。

delegate 异步跑完 / 失败 → 出现，并唤醒父对话
delegate 被用户停止 → 出现；不唤醒（本稿）
await_job 拿到结论 → 不出现（结果在工具卡里）
interrupt（模型叫停）→ 不出现（只回 accepted，不回传内容）

interrupt 只负责停下：它说到哪算哪，不回传内容。模型想要结论时本来就有别的工具——await_job 等到结束、send_message 让它尽快收口——所以停止本身不需要一条结果行。

① delegate 异步完成：出现

deepseek-flash12:57:45
我已经派了一个子代理去做这件事，完成后我把结果整理给你。
子代理已完成 · 工作区文件探索

② await_job：不出现

deepseek-flash12:58:02
我等它，拿到结论就直接回答你。
await_job · 结果
{ "status": "completed", "payload": { "text": "工作区根目录有 12 个文件…" } }
没有分隔线：结果已经在工具卡里。

③ interrupt：不出现，只确认收到

deepseek-flash12:58:20
它跑偏了，我先让它停下来。
interrupt · 结果
{ "status": "accepted", "job_id": "child-7" }
没有分隔线：模型自己叫的停，它知道自己停了。

④ 用户停止子代理：出现，但不唤醒父对话

deepseek-flash12:59:10
子代理正在跑，完成后我把结果整理给你。
子代理已取消 · 工作区文件探索
到此为止：父对话等到你下一次说话时才读到这条线。

// 协调器：结算一段
_finish(entry, phase, reason):
  brief = 最后一行的非空助手文本

  if entry.waiters > 0:        // await_job 正等着
      return
  if entry.stoppedByModel:     // interrupt 发起的停止
      return

  write_row(outcome: phase, brief: brief)   // 用户取消也走这里

  if phase in {completed, failed}:
      enqueue_follow_up()
  // 取消：不唤醒。用户刚按了 Stop，再生成一轮与意图相反；
  // 这条线已在历史里，用户下次发言时模型读得到。

// 父对话自己的 Stop 级联：cancelChild 标记来源，仍然不唤醒
