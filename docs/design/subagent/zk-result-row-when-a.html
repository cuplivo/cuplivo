结果行何时出现

分隔线不是“子代理结束了”的装饰，它只负责把模型还不知道的结果送进对话。模型已经通过工具调用拿到结果时，它不该出现。

规则：结果行只在模型没有通过工具调用拿到结果时出现。
delegate 异步跑完 → 出现；await_job 拿到结论 → 不出现；interrupt 自己叫停 → 不出现。

① delegate 异步完成：出现

deepseek-flash12:57:45
我已经派了一个子代理去做这件事，完成后我把结果整理给你。
子代理已完成 · 工作区文件探索

② await_job 拿到结论：不出现

deepseek-flash12:58:02
我等它，拿到结论就直接回答你。
await_job · 结果
{ "status": "completed", "payload": { "text": "工作区根目录有 12 个文件…" } }
没有分隔线：结果已经在上面这张工具卡里。

③ interrupt：不出现

deepseek-flash12:58:20
它跑偏了，我先让它停下来。
interrupt · 结果
{ "status": "accepted", "job_id": "child-7" }
没有分隔线：停止是模型自己发起的，它知道自己停了。

伪代码

// 协调器：结算一段
_finish(entry, phase, reason):
  brief = 最后一行的非空助手文本

  if entry.waiters > 0:        // await_job 正等着，结果由它带回
      return                    // 不写行、不唤醒

  if entry.stoppedByModel:     // interrupt 发起的停止
      return                    // 不写行、不唤醒

  write_row(outcome: phase, brief: brief)   // 只有这里写分隔线
  if phase in {completed, failed}:
      enqueue_follow_up()        // 让父对话接着读它

// interrupt 的返回值：只确认收到，不等待
interrupt(job_id):
  entry.stoppedByModel = true
  cancel(entry.child)
  return { status: "accepted", job_id }

代价：模型知道“停了”，但不知道停下前它写到了哪一步；那部分只留在子会话里，点开才看得到。分隔线与结果行不再负责“停止”这件事。
