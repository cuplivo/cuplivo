结果行何时出现

分隔线不是“子代理结束了”的装饰，它只负责把模型还不知道的结果送进对话。模型已经通过工具调用拿到结果时，它不该出现。

规则：结果行只在模型没有通过工具调用拿到结果时出现。
delegate 异步跑完 → 出现；await_job 拿到结论 → 不出现；interrupt 等到停下、把结论带回 → 不出现。

① delegate 异步完成：出现

deepseek-flash12:57:45
我已经派了一个子代理去做这件事，完成后我把结果整理给你。
子代理已完成 · 工作区文件探索

② await_job 拿到结论：不出现

deepseek-flash12:58:02
我等它，拿到结论就直接回答你。
await_job · 结果
{ "status": "completed", "payload": { "text": "工作区根目录有 12 个文件…" } }
没有分隔线：结果已经在上面这张工具卡里。

③ interrupt：不出现，且带回停下前的内容

deepseek-flash12:58:20
它跑偏了，我先让它停下来，看看它手上有什么。
interrupt · 结果
{ "status": "stopped", "text": "已经梳理了目录树的前两层，第三层还没开始…" }
没有分隔线：结论已经在这张工具卡里，模型和用户都看得到。

伪代码

// 协调器：结算一段
_finish(entry, phase, reason):
  brief = 最后一行的非空助手文本

  if entry.waiters > 0:        // await_job 正等着，结果由它带回
      return                    // 不写行、不唤醒

  if entry.stoppedByModel:     // interrupt 发起的停止
      return                    // 不写行、不唤醒

  write_row(outcome: phase, brief: brief)   // 只有这里写分隔线
  if phase in {completed, failed}:
      enqueue_follow_up()        // 让父对话接着读它

// interrupt 的返回值：等到这一段真的停下
interrupt(job_id):
  entry.stoppedByModel = true
  cancel(entry.child)
  await settle_or_timeout(2s)  // 本地取消通常远快于这个上限
  return { status: "stopped", text: brief_or_empty() }

代价：interrupt 从“立即返回”变成“等到停下”，工具说明要跟着改；好处是模型和用户都在工具卡里看到停下前的结论，分隔线就不必再补一条“已停止”。
