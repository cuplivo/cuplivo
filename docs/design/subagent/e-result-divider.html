侧边栏与配置（与你说的对齐）

侧边栏是单行。_ChatTile 只有标题 + 可选的小标签 + 时间（side_drawer.dart:4987-5022），没有头像也没有预览行——我上一版画的两行是错的。子代理 三个字就放在 composerDraftLabel 那个位置（11px、cs.primary），零结构改动。

配置收成一个入口。工具箱里一行：子代理 · 继承本助手 · 深度 1 · 完成后通知，点进去是这个弹窗。深度 / 模型 / 完成后 三项都在弹窗里，不在列表里铺三行子行。

图标：Lucide.Bot——适配器里已经有了（lucide_adapter.dart:33），不用画新的。

消息身份：这就是群聊那套「作者」机制

你问的 user 消息 + extra body，仓库里已经有一个跑着的答案：群聊把别人的发言存成 role: 'user' + senderId，序列化时打上 _groupPeerSender（message_builder_service.dart:653-665），再由一个统一的判断 isUserInputMessage 把它排除在「用户自己的话」之外（request_image_context.dart:35-49）——附件、图片、修订 id、「最后一条用户消息」全走这一个谓词。子代理结果就是同一种东西。

  • 存：role: 'user'，id = subagent-result:<childConversationId>（幂等：同一个子代理只会插一次，重复投递天然去重）。
  • 发：wire 上就是 user，带一个内部标记，provider 在出站前剥掉（chat_completions_api.dart:368 已经这么剥 _groupPeerSender）。
  • 不接管：不要修订 id（internalRevisionIdKey）、不接管附件与图片、不成为「最后一条用户消息」。这三条是那个 else if 分支里必须加的。
  • 不新增列、不进 extras：id 前缀就是身份，ContextOperation.summaryPrefix 已经是这个先例。

这一版定下的

  • 结论是一条分隔线：不占视线，不冒充任何人的发言；结论本身要点开才看得到。
  • 时间线里 delegate 是普通工具卡，不覆写渲染；运行态交给输入框上方那条。
  • 父还在跑时，结果排队到当前工具调用结束、在下一个 step 的边界插入（你说的规则）。
  • ask_user 不再需要禁用：子会话是能交互的真会话，它在那里等回答（见下）。

必须接受的代价

  • D 的意义被削弱一半：你说要「结果自己走进会话」，可一行分隔线上只有一个标题——用户还是得点一下才看到结论。
  • 分隔线的语言本来是「上下文被改写了」这种机器事件（压缩、清空）；把一条内容塞进去，语义上有点借。
  • 长结论彻底不可见：只有标题 + 打开。想扫一眼回复的人会烦躁。
  • 父模型读到的是 user 轮次，界面却一个字都没说——两边的心智不一致，以后解释起来要花口舌。

ask_user 与审批：异步之后不用禁了

上一版写「子代理里禁用 ask_user」，前提是 wait-only（父会话被挡着，没人能答）。改成异步之后这个前提没了：ask_user 在子会话里就是一张普通的提问卡，子轮次停在那里等；父会话早就往下走了，没被挡住。审批卡同理（_matchingApprovalRequest 按 conversationId + toolCallId 匹配，子会话自己就能弹）。父卡/条上只需要一个「它在等你回答」的状态，别做透传——透传要在父会话里再造一张卡，还得决定「父会话已经结束了，这张卡算谁的」。

代价：没人打开子会话，它就那样停着，不花钱也不再产出；父会话的条会一直显示它在等。这是可解释的，比「静默挂起」好。

两个变体共用：普通工具卡 + 输入框上方条 + 侧边栏单行标签 + 配置弹窗、wire 上是 user + 标记、排队到 step 边界插入、ask_user 不禁用。这个变体唯一要你定的：结论画成一条分隔线（E），还是一条回复（F）。
