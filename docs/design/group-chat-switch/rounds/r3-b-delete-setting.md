# 第 3 轮·B｜删掉「自动切换话题」，点 owner 一律切到它的列表

> 最彻底地满足 I5：没有设置，就没有「显示着但不生效」的可能。
> 但它同时改掉多数用户的现状，并且与目标书 §4 的横切验收冲突，需要你明确豁免那一句。

## 1. 改完之后

| 布局 | 点助手 / 点群 |
| --- | --- |
| 桌面·话题在左 | 一律切到话题 tab（侧栏收着就先展开） |
| 桌面·话题在右 | 一律打开右侧面板并停在「话题」页 |
| 移动 | 关抽屉（抽屉里没有 tab，行为不变） |

设置行、`desktopAutoSwitchTopics` 字段、pref 键、`displaySettingsPageAutoSwitchTopicsTitle`
文案与 settings 搜索索引条目一起删除（I6 不留无用开关）。

## 2. 为什么有人会想要它

- 「点了一个 owner，却看不到它的会话」本身没有道理；今天之所以需要这个设置，
  是因为切视图在右布局会占宽度、在左布局会跳 tab——那些都是布局的代价，不是一个偏好。
- 设置项本身是成本：一个只有桌面、只有部分布局、默认关闭、标题还叫「自动切换话题」的开关，
  用户无法从标题推断它到底切什么。
- 少一个设置项就少一个"它为什么不生效"的问题类别。

## 3. 代价（这是本变体的全部重量）

- **默认是关的**，所以删掉它 ≈ 对多数现有用户改变行为：点一下 owner，侧栏/面板会动。
  目标书 §4 的横切验收写着「开关关闭时，行为与今天逐格相同」。选 B 必须**明确豁免**这一句
  （把它限定为「切换助手时新建对话」那个开关）。
- **删除文案 = 动 13 个语言的 ARB**（`app_en` / `zh` / `zh_Hant` / `ja` / `ko` / `ru` / `tr` …），
  必须 `flutter gen-l10n` 重新生成并提交生成物；同时删 settings 搜索索引里的条目。
- 右布局的宽度跳变从"用户可选"变成"每次点 owner 都会发生"，是比 A 更频繁的布局抖动。
- 与「保留用户选择」的一般倾向相悖：这个设置是 4.5.0 起就存在的偏好，
  删它是一次产品决策，不是一次修复。

## 4. 与 A 的关系

两者的 reveal 实现完全相同（同一个 `revealTopics()`），差别只在**它前面那个 if**：
A 读设置，B 不读。所以选 B 之后如果后悔，回到 A 只是把 if 加回来 + 恢复文案，
但已删的 ARB 文案要重新加回 13 个语言。

## 5. 适合

认为「点 owner 就该看到它的列表」是产品的默认行为、不需要开关，
并且愿意为此豁免目标书 §4 的一句横切验收。
