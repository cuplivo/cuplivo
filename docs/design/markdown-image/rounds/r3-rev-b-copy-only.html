决策 3 修订 · 方案 B

选区：只做复制

给预览套上通用选区，只提供复制/复制 Markdown/全选；不引入翻译，也不改 AppSelectionArea 的主逻辑。

只有复制，没有翻译

周会结论：下周把导出流程拆成预览与捕获两种模式，再补一条真实渲染器的集成测试。

复制Ctrl C
复制 Markdown
全选Ctrl A

没有翻译 chip，也没有右键的“翻译”；选区能力停在复制。

为什么这样改

  • 最小改动，风险最低。
  • 但和 ChatMessage 的选区体验不一致：预览没有翻译 chip。
  • 后续补翻译仍然要回到同一个 SelectionSession 改造。
代价：不满足“复制/翻译/其他功能”里的翻译；预览仍比消息少一层能力。
