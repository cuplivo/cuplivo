# 第 4 轮·A｜「切换助手时新建对话」按字面执行：点哪个助手，就开它的一张新会话

> 目标书 §4 的 A 行写的是「该助手的 1:1（**新或最近**）」——这一格今天没有唯一答案，
> 而测试必须断言一个。本变体取「新」，也就是这个开关今天在 1:1 之间的含义，原样保留。

## 1. 规则

| 开关 | 点助手 A 时 | 点群 G 时 |
| --- | --- | --- |
| **开** | 一律开 **A 的新会话**（空草稿；连点复用同一个空草稿，不会堆出一串空会话） | 与开关无关：G 的最近话题，没有就新建 |
| **关** | A 的最近 1:1；没有就开新会话 | 同上 |

- 「新」= 新建一张该助手名下的会话，与当前会话的 owner 是否就是 A **无关**。
  在 A 的会话里再点一次 A，也是一张新的空会话——这是今天开关开着时的行为。
- 群不受这个开关影响（群没有「助手切换」这回事），与今天一致。

## 2. 为什么是「新」

- **这个名字就是它今天的意思。** 英文 `New chat when switching assistants`、中文「切换助手时新建对话」；
  打开它的人要的是「我点谁，就从谁那里重新开始」，不是「回到上次那一页」。
- **修复不该顺手改无关行为。** 目标书 §4 的横切要求是「开关关闭时行为与今天逐格相同」；
  这个变体把同样的克制用在开关开着的一半：只修「落在群里」这个错，其余逐格不动。
  于是这次的回归面可以精确描述为「开关开着时，从群话题点助手 → 现在开该助手的 1:1」。
- **它让「新会话」这个词仍然可达。** 若改成「只在换助手时新建」，那么在你已经在这位助手的
  会话里时，`新建` 这个动作就没有入口了——那不是这个开关的语义，是另一个功能。

## 3. 代价

- 开关开着时，「点当前这位助手」与「点另一位助手」的行为一样（都会开新的空会话）。
  想回到这位助手最近的会话，得在侧栏话题列表里点它——这与开关关着时的行为不同，
  但**与今天完全相同**。
- 目标书 §4 的 A 行要按「新」写死，并在表驱动测试里断言「开关开 + 助手有历史 → 打开的会话
  ≠ 该助手最近的会话」。B 变体断言的是相反的一格。

## 4. 与各行的关系

| 验收行 | 本变体的结果 |
| --- | --- |
| A 群话题 → 点助手（开，有历史） | 该助手的**新** 1:1 |
| B 群话题 → 点助手（关，有历史） | 该助手**最近**的 1:1 |
| C 群话题 → 点助手（助手无历史） | 该助手的新 1:1（与开关无关） |
| F 1:1 → 1:1 | 开：新会话；关：最近。与今天逐格相同 |
