这一版定下的

  • 派出去就结束本轮：输入框立刻可用，子代理可以跑很久，多个任务可以并行派出。
  • 与 DSH 同形（先回 started subagent，最终答复走完成通知），以后做子代理间通信时事件流已经在了。
  • 父会话的 Stop 不再等于停掉子代理——取消要另给入口，反而更清楚。

必须接受的代价

  • 父模型的答复不是答案。「已经派了」在结果回来之前什么也没解决，用户得自己判断这话说完了没有。
  • 「谁在说话」要现定。结果到达是第二条 assistant 消息：算子代理说的、算父助手转述，还是算一条系统回执？三种读法三种 UI。
  • 多一个没人按按钮的计费。自动续跑父模型意味着用户不在场时也花钱；不续跑，结果可能被划过去没看见。
  • 写入落在一条空闲会话上。这可能正被 LAN sync / 备份 / 压缩动到；而且以后要做重试、要防重复投递，都得自己造一套。

分水岭

B 是用户先走，结果后到。好处是这个会话从头到尾属于用户；代价是「结果」不再是回答，而变成一条新消息——而那套送达机制，仓库里只有半个先例。

两个变体共用：同一个工具名 delegate、继承父会话的助手与工作区、深度上限默认 1、子会话禁用 ask_user 与审批类工具、幂等键 = 父会话 + 消息 + toolCallId、中断由渲染层派生而不落库。这个变体唯一要你定的：父会话是等，还是不等——选了 B，就得连「送达后要不要续写」一起定。
